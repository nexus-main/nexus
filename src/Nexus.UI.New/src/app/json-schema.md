# JSON Schema Editor Contract

`JsonSchemaEditorComponent` (`app-json-schema-editor`) is a standalone controlled Monaco YAML editor.

- Inputs: `schema: unknown`, `value: unknown`, `rawText: string | undefined`, `themeMode: 'dark' | 'light'`.
- Outputs: `valueChange: unknown`, `rawTextChange: string`, `validityChange: ConfigurationValidation`.
- A defined `rawText`, even an empty string, is authoritative. Store it per registration and bind it back. Set it to `undefined` only to load `value` instead.
- `valueChange` emits only safely parsed JSON-compatible YAML, but that value may be schema-invalid. Invalid YAML drafts emit only `rawTextChange` and invalid validity. A parent must validate all registrations, not just the open editor, before saving.
- Rendering and receiving inputs never create values, inject defaults, or emit value changes. `rawText` remains the editable draft; `value` is only the last parsed JSON-compatible configuration.
- YAML is parsed with the core schema, unique keys are required, aliases are bounded, and the resulting value must be plain JSON: null, booleans, strings, safe numbers, arrays and plain objects only. Empty YAML is invalid because configuration roots must be present.
- All numeric scalar sources in the YAML AST, including flow mappings/sequences and mapping keys, are checked before `toJS` conversion. Unsafe integers, overflow, underflow, negative zero, and decimals that change after a Number/string round trip are rejected so no rounded/reinterpreted value is emitted. Safe YAML numeric spellings (including hexadecimal/octal integers) are supported; quoted strings and literal/folded block strings are not mistaken for numbers.
- The toolbar offers `Generate scaffold` and `Format YAML`. Generating a scaffold requires explicit confirmation to replace the whole draft, and uses a Monaco edit with undo stops rather than clearing undo history. The old field picker, insertion buttons and misleading reset-to-last-parsed-value action are removed.
- `monaco-yaml` provides schema completions, hovers, formatting, folding and document symbols. A root-scoped service registers it once, associates schemas with exact model URIs, and removes associations and models when editors close. Angular bundles the YAML worker; `ngx-monaco-editor-v2` loads Monaco itself and its other workers. Remote schema fetching is disabled. Worker routing is installed after AMD loading, which overwrites `MonacoEnvironment`. A scoped adapter redirects monaco-worker-manager 2's legacy factory call to Monaco 0.55's public `createWebWorker`; the global internal factory must not be replaced.
- Ajv remains the save-blocking validation authority because its .NET formats and numeric policy differ from generic YAML validation. Errors are listed below the editor and emitted through `validityChange`; the previous arbitrary error-index-to-line markers are removed. Language-service validation provides advisory inline diagnostics; its format checks can differ from Ajv. No custom CodeLens or diagnostic quick fixes are added.

## Schema Scaffolds

`createSchemaScaffold(schema: unknown): unknown` explicitly creates a new, deterministic JSON-compatible draft for the editor's confirmed replacement action. It does not modify the schema or inject values during validation/rendering.

- Valid non-null `default`, `examples` in order, and `example` annotations take precedence over generic shapes. Validation uses the original root and applicable fragment paths, including references and constraints, without coercion. An accepted annotation is deep-cloned verbatim: no missing properties are added, union discriminators or types are not changed, and arrays retain their entire contents and length (including empty arrays). Nested null members are preserved. Parent literals are returned whole, not expanded into child seeds. Null or invalid annotations are skipped.
- Without a valid annotation, generic objects include all declared properties, not only required ones. Required names without a property declaration use the applicable additional-property schema.
- Dictionaries with schema-valued (or explicitly true) `additionalProperties` get one `example_key` when otherwise empty. Pattern-only dictionaries also get `example_key` using the first pattern's value schema, without claiming the key matches that pattern. Explicit required names and object examples can supply actual schema-derived names; titles, descriptions, property names and extension annotations are not interpreted as naming conventions. Closed objects and `maxProperties: 0` do not get synthetic keys.
- Generic arrays contain one recursively generated item, even when `minItems` asks for more. `maxItems: 0` produces `[]`; forbidden items also produce `[]`. Tuple schemas use their first item. These rules apply only when no valid annotation is available.
- Enums prefer a valid annotation, otherwise the first valid non-null member, falling back to null. Enum members are also cloned literally rather than expanded.
- Root/local JSON Pointer `$ref`s (including URI/pointer escaping) are resolved with Draft 4 sibling-ignore behavior. `allOf` combines known fields and constraints; generic `oneOf`/`anyOf` generation selects the first expandable non-null branch in schema order. Type arrays likewise prefer the first non-null type only for generic generation; a validated annotation can use another branch or type. This separate traversal intentionally supports more shapes than the conservative `getSchemaView` projection. It does not search every branch combination or guarantee `oneOf` exclusivity.
- Basic placeholders are empty strings, false, and numbers near zero adjusted for feasible bounds/multiples. String lengths are bounded. Known formats get fixed examples, including .NET `duration`/`time-span` and `time` as `00:00:00`, and timezone-free `date-time` as `2000-01-01T00:00:00`. Dates remain strings; generation never reads the clock or uses randomness.
- Recursive references/JS cycles terminate with null; independent uses of the same definition still expand independently. Traversal has a depth limit of 24 and a shared 4096-work-unit budget, with generated strings capped at 4096 characters. Exhausted children become null and remaining fields may be omitted. A bounded preflight also checks schemas/annotations before passing them to Ajv or cloning; oversized/deep/cyclic inputs disable annotation validation, not structural generation. Returned objects use own-property construction, so `__proto__`, `constructor`, empty names and other keys cannot mutate prototypes. No returned object/array shares mutable storage with the schema.

This is an **editable scaffold, not a universally valid instance or a schema solver**. Patterns, conflicting intersections, dependencies, complex numeric constraints, array cardinality, exclusive unions, required recursion and other constraints may need manual repair. Unsupported/malformed shapes, unresolved/external references and nested `id` scopes fall back to null; no remote schema is fetched. Empty/unconstrained schemas use null. Annotation validation remains subject to the Draft 4 validator's dialect/format limitations described below. Always run `validateConfiguration` on the edited result before saving.

## Pipeline Transport Boundary

Use `parseJsonSafely` on the response text **before** any transport `JSON.parse` or `Response.json()` for **GET `/api/v1/sources/pipelines` only**. A lazy `import('./json-schema')` exposes the same pure helper used by raw editing. It returns `{ valid: true, value, errors: [] }` or `{ valid: false, errors: string[] }`. On failure, do not fall back to ordinary parsing.

Do not apply this parser to source descriptions/schema responses. NJsonSchema commonly includes Int64 minimum/maximum bounds outside JavaScript's safe-integer range. Schemas remain unmodified, and ordinary description transport parsing is retained. Ajv evaluates numeric bounds as JavaScript numbers; safe configuration integers cannot reach the usual Int64 endpoints, but arbitrary high-precision decimal schema constraints are not exact arithmetic.

The JSON transport parser checks numeric tokens before JSON.parse without relying on the newer reviver context API. It rejects unsafe integers (even exactly representable integers outside the safe range), overflow, underflow, negative zero, and decimals whose normalized decimal value differs after a Number/string round trip. It accepts ordinary decimals such as `0.1`, not arbitrary-precision binary-exact arithmetic. Numeric values rounded by an earlier parser cannot be recovered. Duplicate JSON object names follow JSON.parse's last-name-wins behavior; this is not a general lossless JSON syntax tree.

`multipleOf` uses exact BigInt divisibility of normalized decimal Number round-trip tokens, including negative values and scientific notation. For example, `0.3` is a multiple of `0.1`, but `0.30000000000000004` is not. No epsilon tolerance is used. This does not recover precision already lost while parsing schema metadata; the divisor is interpreted from its received Number's decimal representation.

## Format Policy

Unknown formats fail closed with an explicit schema error, including formats in optional fields and definitions. `strict: false` is retained for NJsonSchema annotations/keywords, but does not permit silent unknown-format acceptance. `$ref` siblings are ignored under Draft 4 semantics, subject to the limitation below.

- Standard formats supplied by `ajv-formats` use its full validators unless overridden below: date, URI, email, hostname, IP, UUID, regex, JSON pointers, byte/base64, and its other registered standard formats. `guid` is an alias of the same UUID validator, including its accepted UUID/URN forms; it is not a general CLR Guid.Parse implementation.
- `time` accepts `hh:mm:ss[.fffffff]` (TimeOnly) with an optional `Z` or `+/-hh:mm` offset. `date-time` accepts `yyyy-MM-ddT` followed by that time, including timezone-free DateTime.Unspecified. Checks enforce the Gregorian calendar, years 0001-9999, hours 00-23, minutes/seconds 00-59, one to seven fractional digits, and offsets up to +/-14:00. Leap seconds, omitted seconds, lowercase separators, whitespace separators, compact offsets and fractional precision above seven digits are rejected. These are explicit .NET-aware lexical policies, not strict RFC3339 or full CLR parser emulation. Strings are never normalized or converted to Date objects. Offset-bearing time-only values may still require a backend type other than TimeOnly; date-time offset conversion at year boundaries is left to the backend.
- `time-span` validates the invariant .NET constant form `[-][d.]hh:mm:ss[.fffffff]`, including component ranges, up to seven fractional digits, and the signed Int64 tick limits using BigInt. Culture-specific forms and abbreviated hours/minutes are not supported.
- `duration` accepts either that .NET TimeSpan form (NJsonSchema/ASP.NET usage) or the ISO/RFC duration syntax supplied by `ajv-formats`. The latter accepts whole-component durations such as `P1D`, `PT1H`, and `P1W`; it does not accept fractional ISO seconds or negative ISO durations. No conversion or normalization is performed. This is an explicit union policy, not a guarantee of backend deserialization for every ISO duration.
- `int32` is range/integrality checked by `ajv-formats`. `int64` is integral and additionally subject to the configuration helper's safe-integer restriction. `uint64` validates nonnegative safe integers. The full .NET Int64/UInt64 ranges are deliberately unavailable as JSON numbers. Quoted numbers are permitted only when the original schema accepts strings.
- `decimal` is a known finite-number representation annotation subject to the same safe-integer and decimal round-trip policy, explicit schema bounds and exact decimal multipleOf checks. It does not promise CLR Decimal's 96-bit coefficient, scale 0-28 or full precision. For example `1e-29` is allowed unless constrained by the schema, but a high-precision raw decimal that would round is rejected. No implicit CLR Decimal range/scale constraints are injected.
- Numeric `byte` needs explicit `type: integer`, `minimum: 0`, `maximum: 255` in the backend-generated schema. Ajv's `byte` format validates base64 strings only; the UI does not rewrite schemas or claim numeric bounds from that format alone. Explicit bounds are tested, and string/base64 behavior is unchanged.
- `float` and `double` are known numeric representation annotations, not guarantees of CLR range or Float32 exactness. JSON number safety and explicit schema bounds still apply. `password` and `binary` are known string annotations, not content validators; the editor does not promise password masking or binary decoding. Schema `type`, `pattern`, and other constraints remain active.

## Other Limits

Validators are cached by root schema identity; supplied schemas must be treated as immutable. Missing schemas, unresolved refs, unsupported dialects and compilation failures fail closed. There is no remote ref fetching or save override.

OpenAPI `nullable` is not a Draft 4 keyword. Ajv applies it in its type compiler even when the keyword is removed, so schemas containing it fail closed (for both true and false) rather than silently gaining OpenAPI semantics. Use Draft 4 null type unions or anyOf/oneOf instead. Presence choices also fail closed for such schemas.

Ajv's legacy Draft 4 `$ref` sibling-ignore option still applies a sibling `type` incorrectly. Schemas containing that combination fail closed with an explicit message rather than applying incorrect semantics or rewriting the schema. Single-branch `oneOf`/`anyOf` ref wrappers generated by NJsonSchema are supported.

The older `getSchemaView` projection remains conservative; the YAML editor no longer uses it for field insertion or cursor-path inference. Schema scaffolding and language-service assistance do not bypass original-schema validation. Defaults are used only through explicit scaffold generation or language-service suggestions, never during loading or validation.

Enum labels prefer `x-enumDisplayNames`, then `x-enumNames`, then the JSON value. Only annotation arrays aligned in length with the original enum are used; labels remain aligned when null or invalid entries are filtered. Labels never replace stored enum values or weaken validation. Integer schemas with `x-enumFlags` but no enum use the ordinary integer input; an actual enum still rejects undeclared flag combinations. No flags multi-select is provided.

Verification uses pure Node tests and Angular template/type compilation. Browser focus, visual layout and runtime interaction tests are not included.
